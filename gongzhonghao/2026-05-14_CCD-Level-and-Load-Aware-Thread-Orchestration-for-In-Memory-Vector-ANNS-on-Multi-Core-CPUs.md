# 小红书揭秘：CCD感知线程编排如何让向量检索性能飙升3.7倍，延迟锐减90%

现代搜索引擎、推荐系统和广告服务都离不开向量近似最近邻搜索（ANNS）。随着业务规模持续增长，业内纷纷转向基于Core-Complex Dies（CCD）架构的多核CPU以提升吞吐量。然而，小红书的研究人员发现，简单增加核心数并不能带来线性的性能提升，甚至会出现严重的资源浪费。

一篇来自小红书研究团队的论文，深入剖析了CCD架构下向量搜索的性能瓶颈，并提出了一套名为**CCD-Level and Load-Aware Thread Orchestration**的线程编排框架。该框架在真实生产环境中，实现了吞吐量最高**3.7倍**的提升，并将P50和P999延迟降低了**30%至90%**。该方法的核心在于：必须从硬件架构和负载特征的双重视角出发，进行“协同设计”式的线程编排。

## 一、核心方法：三位一体的线程编排

**1. 统一的CCD级任务提交接口** 与以往针对不同索引（如HNSW、IVF）采用不同调度策略的做法不同，该框架设计了一个统一的接口。它巧妙地将HNSW的整个查询任务和IVF的单个聚类扫描任务，都抽象为带有“Mapping_ID”的独立任务。无论哪种索引，任务提交的流程完全一致，使得调度层与索引逻辑解耦，极大地提升了框架的兼容性和可迁移性。

**2. 缓存友好的任务分发与动态负载监视**

这是框架性能提升的关键。论文揭示了真实流量中一个重要的负载特征：**内存访问具有高度局部性，且分布极度不均衡**。短时间内，大量查询会反复访问同一个向量表的“热点”区域。在CCD架构下，每个CCD拥有独立的末级缓存（L3 Cache）。如果所有“热点”任务都被分配到同一个CCD，会引发缓存激战（Cache Pollution），导致大量数据被频繁驱逐。相反，如果将一个“热点”任务与一个“冷点”任务配对到同一个CCD，热点数据就能“独享”CCD内的绝大部分缓存空间。

为此，该框架通过持续监控每个任务的实时内存流量，采用一种“**冷热配对**”的动态映射算法。该算法每次都会将最“热”的任务与最“冷”的任务进行配对，并均匀分配到不同CCD上，从而最大化缓存利用率，显著降低跨芯片的数据访问延迟。

**3. CCD感知的任务窃取策略**

在负载不均衡时，传统的工作窃取（Work-Stealing）策略会允许任意空闲核心从其他核心窃取任务。但在CCD架构下，这种“无脑”的跨芯片窃取会带来灾难性后果：被窃取的任务数据可能原本在受害者核心所在的CCD缓存中，窃取到新CCD后，数据需要重新从主存加载，导致严重的缓存未命中。

因此，该框架制定了一个“**亲CCD**”的层级化窃取策略：任务窃取优先在同CCD内的核心之间进行，只有当同CCD内所有核心都空闲时，才允许跨芯片窃取。这种做法在保证负载均衡的同时，最大程度地保护了缓存温度，避免了不必要的内存访问。

## 二、实验：来自真实世界的性能飞跃

研究团队在AMD 4代EPYC 96核处理器和2代EPYC 48核处理器上，使用来自搜索、推荐和广告服务的真实生产流量进行了详尽评估。

- **吞吐量提升**：在96核处理器上，HNSW索引的吞吐量从约60K QPS飙升至超100K QPS，IVF索引也实现了近**3倍**的提升。
- **延迟显著降低**：端到端延迟测试显示，新版框架在所有延迟分位点上都实现了大幅降低，P50和P999延迟的降低幅度高达**30%到90%**。
- **缓存和CPU效率优化**：底层分析揭示了性能提升的根本原因。论文提出的框架将L3缓存未命中率降低了**6%至30%**，并将CPU停顿周期减少了**20%至80%**。更重要的是，跨CCD的任务窃取比例从超过75%被有效抑制到了**5%以下**。

## 三、展望：硬件与软件的“协奏曲”

这项研究为现代数据中心应用指明了方向：在硬件架构日趋复杂的今天，软件优化不应再局限于算法层面，而必须深入理解并主动适应底层硬件的拓扑结构和特性。

这套框架已成功在小红书的生产环境中大规模部署，并带来了显著的性能与成本效益。对于那些同样面临着“加核心却不增效”困境的向量搜索、图计算等内存密集型应用而言，**从“硬件感知”的视角重新审视线程编排，或许就是下一代性能突破的关键所在**。对于正在考虑升级硬件或优化现有系统的开发者来说，这无疑是一个值得深入探索的方向。
