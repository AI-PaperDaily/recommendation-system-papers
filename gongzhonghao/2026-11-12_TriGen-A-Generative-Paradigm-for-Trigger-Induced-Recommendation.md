# 阿里国际 TriGen：让触发商品持续引导生成式推荐，六国线上收入加权提升3.27%

## 一、引言

用户在商品流中点击一块手表，进入后续推荐页面后，平台应该推荐什么？手表和表带与这次点击直接相关；但如果用户长期偏爱运动装备，运动手环也可能值得推荐。此时，系统既要理解点击带来的**即时意图**，也不能完全丢掉用户的历史偏好。

这种由一次交互打开后续商品流的场景，被称为**触发式推荐**（Trigger-Induced Recommendation，TIR）。传统生成式推荐通常依据用户历史，逐步生成目标商品的语义 ID；而既有触发式推荐方法主要面向点击率打分，难以直接控制逐 token 的生成过程。

TriGen 针对这一缺口，在编码、偏好融合和解码三个阶段引入触发信息，尝试解决“延续历史兴趣”与“响应当前点击”之间的矛盾。

## 二、核心方法

生成式推荐首先将商品映射为多级离散的**语义 ID**（Semantic ID）。模型按顺序预测各级 token，再将生成的 ID 映射回商品。语义 ID 通常通过残差量化获得：前面的 token 提供初步表示，后面的 token 逐级补充细节，但各级并不一定对应人工定义的品类或属性标签。

TriGen 沿用这一生成方式，同时将触发商品作为明确的条件信号。其关键不只是“把点击商品加入输入”，而是让触发信息在不同阶段承担不同作用。

![图2：TriGen的编码、双路径融合与逐位置解码结构](https://arxiv.org/html/2611.16395v1/trigen.png)

### Calibrated Tail Injection：在序列尾部校准触发强度

一条长历史中只有一个触发商品时，它的信号可能被大量历史行为稀释。TriGen 的做法是：将触发表示重复放在历史序列尾部，并保持上下文窗口长度不变。

设历史窗口长度为 $M$，触发表示为 $e^{trg}$，重复次数为 $N$，输入序列为：

$$\tilde{H}=(h_{N+1},\dots,h_{M},\underbrace{e^{trg},\dots,e^{trg}}_{N\text{ times}}).$$

这个操作用最早的 $N$ 个历史位置换取触发信息，使模型能够在自注意力中联合处理触发商品和近期行为。

这里有两个互补设计。首先，触发商品位于序列尾部，与近期行为在位置上相邻；编码器使用 **RoPE 旋转位置编码**建模相对位置信息，以支持它们之间的交互。其次，重复次数控制触发表示在注意力计算中所占的容量：次数太少可能不足以突出即时意图，太多则可能挤占历史上下文。

处理后的序列进入双向 Transformer 编码器，得到包含触发上下文的表示，并供后续解码器进行交叉注意力。

### Adaptive Dual-Path Fusion：按请求平衡历史与触发意图

序列编码解决了触发信息如何进入上下文的问题，但不同点击需要的触发强度并不相同。一次偶然点击可能不应覆盖长期偏好；一次明确的购物意图则需要更强的触发引导。

TriGen 因此从**未经过尾部注入的历史表示**中提取两条条件路径：

- **触发路径**：将触发商品映射为不同解码位置的查询，从历史中关注与当前点击相关的行为。
- **历史路径**：使用可学习的默认查询汇总历史偏好，不直接依赖触发商品。

随后，门控路由器先分别汇总两条路径，再为每个语义 ID 位置预测融合权重：

$$\mathbf{w}=\sigma\left(\mathbf{W}_{r}\left[\frac{1}{L}\sum_{j=1}^{L}t_{j}\;\|\;\frac{1}{L}\sum_{j=1}^{L}h_{j}\right]+\mathbf{b}_{r}\right),\quad c_{l}=w_{l}t_{l}+(1-w_{l})h_{l}.$$

该公式表示：对每个生成位置，模型根据当前请求自适应地混合触发路径 $t_l$ 与历史路径 $h_l$，得到条件向量 $c_l$。

因此，同一触发商品面对不同历史时，可以产生不同的条件表示；同一次请求的不同生成位置，也可以使用不同权重。

### Position-Specific Trigger-PFFN：在每一步维持触发引导

语义 ID 是逐级生成的。如果只在起始位置加入触发条件，后续生成步骤可能逐渐受到已生成前缀的主导。TriGen 使用 **Position-Specific Trigger-PFFN**，为每一级设置独立的前馈网络，将融合条件 $c_l$ 转换为对应位置的条件向量 $\tilde{c}_l$。

训练时，模型采用教师强制：上一位置输入真实 token，同时在当前位置加入对应条件：

$$x_{l}^{dec}=\begin{cases}e(BOS)+\tilde{c}_{1},&l=1,\\e(y_{l-1})+\tilde{c}_{l},&l\in\{2,\dots,L\}.\end{cases}$$

这意味着每个解码位置都同时接收前缀信息和位置专属条件，而不只在生成开始时看到触发信号。

独立投影允许不同位置学习不同的条件变换，以适应残差量化各级表示的差异。之后，解码器通过因果自注意力处理生成前缀，并通过交叉注意力读取编码后的历史与触发上下文，逐步预测目标商品的语义 ID。

## 三、实验

离线实验使用真实电商触发式推荐数据，以及 Amazon Reviews 2018 的 Industrial_and_Scientific 类目。后者没有原生触发标注，因此以用户历史中最近一次交互模拟触发商品，预测下一件商品；其结果需要放在这一模拟设定下理解。

评估采用 **Recall@K** 和 **NDCG@K**：前者衡量目标商品是否进入前 K 个结果，后者同时考虑命中商品的排名。推理使用**束搜索**（beam search），即每一步保留多个较优生成前缀，继续搜索候选语义 ID。

在工业数据上，TriGen 的 Recall@5 和 Recall@10 分别为 **5.58%** 和 **15.50%**。相比共享生成骨干、码本和参数预算的简单触发基线，最好的对应结果分别为 **4.46%** 和 **12.15%**。这说明在该数据集上，收益不只是来自“加入触发商品”，还与触发强度、双路径融合和解码方式有关。

在 Amazon 模拟触发数据上，TriGen 的 Recall@5 为 **10.83%**，高于简单触发基线中的 **10.27%**；但 Recall@10 为 **13.22%**，略低于简单追加触发基线的 **13.26%**。因此，公开数据上的结果是多数指标领先或具有竞争力，而非所有指标均为第一。

消融实验进一步检验了各组件。在工业数据上，移除尾部注入后 Recall@10 从 **15.50%** 降至 **11.04%**；移除双路径融合、改用原始触发表示作为解码条件后，降至 **14.51%**。移除 Trigger-PFFN 的变体同时取消了解码阶段的触发条件，Recall@10 为 **11.10%**，因此这一对比支持解码侧条件注入的作用，但不能单独归因于逐位置投影。

更细的设计对比显示，固定平均两条路径、只在起始位置注入条件、以及所有位置共享投影层，均低于完整模型。触发重复次数测试中，工业数据上的各项指标在重复 **3 次**时达到峰值，继续增加则下降；这个最优值属于该实验设置，不代表其他场景也应固定使用 3 次。

![图3：工业数据上触发商品重复次数对离线指标的影响](https://arxiv.org/html/2611.16395v1/fig_repeat_new.svg)

案例分析也展示了历史上下文的作用：面对相同的肩包触发商品，有旅行穿搭历史的用户得到服饰、包和旅行护理用品等结果；历史与肩包关联较弱的用户则得到更集中的包类推荐。案例说明了输出差异，但不能仅凭结果直接确认门控权重如何变化。

![图4：六个国家市场的线上A/B测试结果](https://arxiv.org/html/2611.16395v1/fig_ab.svg)

线上 A/B 测试以已部署的 **GR + trigger append** 生成式模型为对照，在六个国家的触发推荐信息流中进行，每组分配随机抽取的 **10%** 生产流量，上下游服务流程保持一致。TriGen 在六国均取得收入提升，四国 GMV 提升；按流量加权汇总后，收入相对提升 **3.27%**、GMV 相对提升 **0.90%**，汇总指标达到论文报告的统计显著性水平（双侧检验，$p<0.05$）。线上推理延迟约 **10.5 毫秒**，与对照模型接近；随后 TriGen 已全面部署并服务主要线上流量。
