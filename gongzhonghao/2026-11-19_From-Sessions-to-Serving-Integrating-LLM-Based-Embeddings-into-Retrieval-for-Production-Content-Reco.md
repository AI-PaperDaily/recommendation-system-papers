# Autodesk LSER：召回融合LLM会话与历史向量，无LLM版本线上试用启动率+17.1%

## 一、引言

在内容推荐网站上，用户可能先浏览产品介绍，再查看客户案例或学习资料。推荐系统需要从多种内容中找出与当前兴趣相关的候选，但用户行为往往稀疏，单次会话中的意图也可能快速变化。

常见的召回与排序流程先从全量内容中筛选候选，再交给排序模型细排。如果召回阶段没有理解用户正在探索什么，即使后续排序更精细，也无法选中未进入候选集的内容。已有序列模型可以编码浏览过的内容，却不一定能充分利用无法映射到内容库的页面行为。

Autodesk 提出的 **LSER** 在现有召回模型中保留序列编码器，同时加入大语言模型生成的会话和历史向量，并用近线计算更新用户表示。线上实验验证了不含 LLM 特征的版本相对规则引擎的收益；LLM 向量的增量效果则由离线消融单独验证。

## 二、核心方法

LSER 接收用户近期会话、较早历史和请求上下文，输出用于检索内容的用户向量。它把两种行为视角放在一起：一条路径编码映射到内容库的访问序列，另一条路径读取更丰富的事件文本；融合后的向量与预计算的内容向量匹配，产生候选集。

### 从行为记录到召回向量

每条监督样本或线上请求都有一个时间点：当前会话序列只包含该时间点之前、同一会话内的行为；历史序列取当前会话开始之前的较早行为。训练时排除标签之后的事件，避免未来信息进入用户特征。

在原有序列路径中，事件先映射为内容 ID，再查找对应内容的 BGE 文本向量。初始部署使用类似 BERT4Rec 的序列编码器处理会话和历史，分别得到固定长度向量。不能映射到内容库的事件则被丢弃或记为未知项。

内容塔也使用 BGE 编码标题和描述，再结合内容类型等信息生成内容向量；生产配置没有启用可学习的内容 ID 向量。用户塔则将序列向量与用户属性、页面上下文、产品使用情况等信息融合。启用 LLM 路径时，两条路径的结果共同参与融合：

$$
\mathbf{e}_{u}=f_{\text{user}}\big(
\mathbf{e}_{u}^{\text{sess}},
\mathbf{e}_{u}^{\text{hist}},
\mathbf{e}_{u}^{\text{LLM}},
\mathrm{Emb}_{\text{other}}(x_u)
\big).
$$

这里的 $\mathbf{e}_{u}^{\text{sess}}$ 和 $\mathbf{e}_{u}^{\text{hist}}$ 来自原有序列编码器，$\mathbf{e}_{u}^{\text{LLM}}$ 拼接 LLM 会话与历史向量，其余项代表非序列特征；融合结果用于和内容向量计算余弦相似度。

### 用下一事件训练辅助向量

LLM 路径与原有序列路径使用相同的时间窗口，但读取的不是内容 ID，而是按时间排序的**事件类型和事件值文本**。事件类型描述页面浏览、链接点击等动作，事件值描述页面或内容上下文，因此可以保留部分没有内容 ID 的页面行为。

每个事件的类型和文本先由冻结的 Qwen3-0.6B-embedding 模型编码并拼接，再经线性映射输入改造后的 Qwen3 风格解码器。序列末尾加入结束标记，模型对最后有效位置的隐藏状态做池化和投影，得到固定长度向量。会话和历史编码器从同一预训练检查点初始化，但分别训练，最终不共享权重。

训练目标是让已有行为能够识别紧接着发生的事件。训练样本取一段事件前缀，将真实下一事件作为正例，并采样其他事件作为负例。前缀和候选事件经过相应的同一个编码器，使用内积打分，再通过 sigmoid 得到匹配概率 $\hat p_{i,j}$。对样本 $i$ 的候选集 $\mathcal C_i$，正例标签为 1，负例标签为 0，优化目标为：

$$
\mathcal{L}_{\text{seq}}^{\text{LLM}}
=-\frac{1}{N}\sum_{i=1}^{N}\sum_{j\in\mathcal{C}_{i}}
\left[
y_{i,j}\log\hat p_{i,j}
+(1-y_{i,j})\log(1-\hat p_{i,j})
\right].
$$

这一二元交叉熵目标让前缀向量更接近真实下一事件的表示，同时压低采样负例的匹配概率。

完成事件预测训练后，会话和历史编码器被加载进用户塔，与双塔一起按召回目标继续微调。召回训练使用融合多种行为和上下文得到的正向用户—内容样本；同一批次中其他样本的正内容作为负例。对于批次中的第 $k$ 个用户，InfoNCE 损失为：

$$
\mathcal{L}_{k}
=-\log
\frac{\exp\big(\mathrm{score}(u_k,i_k^+)/\tau\big)}
{\sum_{j=1}^{N}\exp\big(\mathrm{score}(u_k,i_j^+)/\tau\big)}.
$$

其中 $\mathrm{score}$ 是用户与内容向量的余弦相似度，$\tau$ 控制分数的区分程度；这个目标推动用户向量靠近其正向内容、远离批内负例。

### 异步更新，在线完成检索

序列编码器和 LLM 路径都需要处理行为序列。若每次请求都同步运行，便会占用紧张的线上推理预算；若只按天更新，又可能跟不上会话内的兴趣变化。

LSER 因此采用**近线更新**：新行为进入特征存储后，异步触发用户编码任务，把序列向量和启用时的 LLM 向量写入向量存储。请求到来时，应用读取最新可用向量，附上请求时特征，由实时端点完成用户塔融合，再通过近似最近邻检索内容向量。

![图2：新行为触发用户向量异步更新，实时端点读取向量并检索](https://arxiv.org/html/2611.26096v1/figures/serving.jpg)

异步更新意味着用户行为不会立即反映在向量中。新向量尚未就绪时，系统可使用最近缓存的向量，或省略可选的 LLM 特征。该设计将编码吞吐与请求延迟分开，但刷新频率仍需在新鲜度和计算成本之间权衡。

## 三、实验

离线消融要验证的是：**在已有序列编码器之上，LLM 向量是否还有增量价值**。对照组和实验组使用相同的特征构造、双塔架构与训练协议，只切换两个各为 64 维的 LLM 会话和历史向量。数据按时间划分为训练、验证和测试集，每条测试记录根据其所属推荐位置允许的候选内容进行检索。

评估按记录计算：**HR@10** 衡量该记录的正向内容是否出现在前 10 个候选中，**MRR** 衡量正向内容的排名。相对不使用 LLM 向量的对照组，热门产品位置的 HR@10 提高 **9.6 个百分点**，MRR 提高 **0.021**；客户成功案例位置的 HR@1 提高 **6.0 个百分点**，MRR 提高 **0.030**。其他位置和指标基本持平，因此收益并非覆盖所有推荐场景。研究者推测，增益可能来自更丰富的事件文本和语义信息，但消融没有分别验证这两种来源。

线上 A/B 则验证另一件事：在 autodesk.com 的 50/50 随机流量中，**未启用 LLM 辅助向量**的初始 LSER 相对旧规则引擎是否有效。该版本保留学习式会话编码和近线服务，首页产品与行业轮播点击率相对提升 **10.3%**，产品试用启动率相对提升 **17.1%**；报告指标均达到 $p<0.05$。这些线上收益属于整体学习式召回相对规则引擎的比较，不能归因于 LLM 向量，后者仍需独立线上实验验证。
