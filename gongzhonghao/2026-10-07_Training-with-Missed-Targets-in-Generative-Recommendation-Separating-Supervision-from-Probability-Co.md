## 生成式推荐训练的隐忧：追加遗漏目标为何反伤排序？7.8%-22.2%性能回升揭示概率竞争陷阱

生成式推荐系统正在重塑大规模Web推荐的架构。当语义ID解码引擎在毫秒级预算内只能返回有限候选集时，漏掉用户可能点击的目标几乎是必然事件。一个直观的补救方案是**候选补全**：训练时把漏掉的目标追加到重排序器的列表中，让模型“见过”这些本该排序的物品。但《WWW 2027》的一篇论文揭示了一个反直觉的发现——**这个看似无害的操作，可能恰恰在伤害推理时真正可服务的物品排序**。更关键的是，论文通过三个精心匹配的损失函数，把“追加监督”与“概率竞争”两个纠缠的效应剥离开来，定位了真正的元凶。

## 一、问题聚焦

生成式推荐器通过生成**语义ID**（semantic IDs）来检索物品。一旦生成器和候选路由固定，推理时重排序器只能看到生成器返回的候选集$N(x)$，而被漏掉的观测目标$A(x) = (Y_x \cap \mathcal{I}) \setminus N(x)$将永远失去排序机会。

候选补全的做法是：训练时保留所有返回物品，将漏掉的目标追加进列表，形成扩充集$C(x) = N(x) \cup A(x)$。但论文指出，这个操作同时改变了三件事——**改变了已检索目标的权重、增加了对追加目标的监督、让两组物品在同一个softmax中争夺概率**。一个简单的“追加/不追加”对比实验，根本无法解释推理排序变化究竟来自哪一项因素。

## 二、方法核心

### 三阶段损失分解：从“全部混杂”到“逐项分离”

论文的核心洞察是将完整列表损失$\mathcal{L}_{\text{append}}$分解为三个独立项。设返回组的目标数为$r = |N \cap Y|$，追加组的目标数为$k = |A|$，则目标分布中返回组占比$\alpha = r/(r+k)$，追加组占比$\gamma = k/(r+k)$。两组内部的归一化损失分别记为：

$$\mathcal{L}_N = -\frac{1}{r}\sum_{i \in N \cap Y}\log p_N(i), \qquad \mathcal{L}_A = -\frac{1}{k}\sum_{i \in A}\log p_A(i)$$

其中$p_N(i) = e^{s_i}/Z_N$，$p_A(i) = e^{s_i}/Z_A$分别是两组内部的softmax概率。完整列表损失的三部分分解公式为：

$$\mathcal{L}_{\text{append}} = \mathcal{T}_N + \mathcal{T}_A + \mathcal{T}_{\text{mass}}$$

其中$\mathcal{T}_N = \alpha \mathcal{L}_N$是返回组加权排序损失，$\mathcal{T}_A = \gamma \mathcal{L}_A$是追加组内部排序损失，而$\mathcal{T}_{\text{mass}}$则是论文所称的**组间竞争项**：

$$\mathcal{T}_{\text{mass}} = -\alpha\log\frac{Z_N}{Z_N + Z_A} - \gamma\log\frac{Z_A}{Z_N + Z_A}$$

### 条件训练：用临时偏移量“拆掉”概率竞争

为了单独研究追加目标监督的效果，论文提出了**条件训练**（Conditional Training, Cond）。构造思路是：给每个训练列表中所有追加目标的得分加上同一个标量$\delta$，将追加组的概率质量调整到目标值$\gamma$，而不改变组内排序。通过解析最小化得到最优偏移量：

$$\delta^* = \log(k/r) + \log Z_N - \log Z_A$$

图2直观展示了这一构造如何将Full中的跨组竞争项剥离，只保留两个组内损失。Cond不存储偏移量，推理时仍只对$s_\phi(i|x) = \ell(i|x) + h_\phi(x,i)$在返回组上应用。

### 三个损失函数的因果链

论文设计的三阶段训练损失分别是：

- **WN**（Weighted-native）：仅保留返回组内部排序，且权重与Full中一致，$\mathcal{L}_{WN} = \alpha \mathcal{L}_N$。
- **Cond**：在WN基础上增加追加组的独立归一化监督，$\mathcal{L}_{Cond} = \mathcal{T}_N + \mathcal{T}_A$。
- **Full**：在Cond基础上加入跨组概率竞争，$\mathcal{L}_{Full} = \mathcal{T}_N + \mathcal{T}_A + \mathcal{T}_{\text{mass}}$。

从WN到Cond只增加一项要求，从Cond到Full也只增加一项要求，这使得差异归因具备严格的因果解释力。为说明竞争项确实会影响推理排序，论文给出竞争项梯度的解析表达式：

$$\nabla_\phi \mathcal{T}_{\text{mass}} = (\pi_A - \gamma)(\mu_A - \mu_N)$$

其中$\pi_A = Z_A/(Z_N + Z_A)$是追加组的预测概率与目标份额的差距，$\mu_B = \sum_{i \in B} p_B(i)\nabla_\phi s_i$是两组平均得分梯度。该梯度更新的是同一个评分器参数，因此即便追加物品在推理时消失，训练中的竞争仍会改变返回物品的排序。

## 三、实验验证

### 主实验设置

论文在RecIF-Ads和Amazon Video Games (A-Games)两个数据集上进行了严格的对照实验。**所有损失共享相同的候选集、训练列表、特征、初始化、优化器和推理池**，只改变训练损失的目标函数。评测指标采用全目标归一化折损累计增益（FT-NDCG@20），其分母包含用户的完整目标集，因此漏掉目标仍会被惩罚。

### 核心发现：竞争造成损害，监督可能有益

在RecIF-Ads数据集上训练60个epoch后，Cond在七次独立训练运行中**全部超过Full**。Cond相对于Full的FT-NDCG提升为+0.007423（95%区间[+0.004978, +0.009744]）。同时，Cond相对于WN的提升为+0.001877（[+0.000343, +0.003455]），七次运行方向一致。这些结果表明：**组间概率竞争是性能下降的主要来源，而追加目标监督本身可能有益**。

### 关键确认：A-Games预注册实验

在A-Games数据集上，论文预先固定了所有设置后开启测试。MLP重排序器上，Cond相对于Full的FT-NDCG增益为+9.177（95%区间[+6.709, +11.651]）；注意力重排序器上，增益为+3.234（[+1.848, +4.651]）。对应的相对提升分别为**22.23%和7.83%**。即便不保留追加损失，WN相对于WN+Mass（即只加入竞争项不加追加监督）的增益也达到+5.834（MLP）和+5.470（Attention）。

### 概率偏移实验：竞争的直接证据

为进一步验证竞争项的作用，论文对每个训练列表给所有追加得分加上同一常数，使其初始概率精确匹配目标份额。**Cond的训练路径和参数保持数值完全一致，证明其对概率划分不敏感；而Full则显著改变**——在A-Games注意力模型上变化幅度为+0.004407（[+0.001591, +0.007177]）。这直接证实了竞争项在训练中发挥着独立且实质性的影响。

### 开发集规则的应用

论文固定了一个保守的切换规则：**只有当追加目标训练的调整后增益下界在开发用户上为正时，才采用该训练方式**。在A-Cell类别上，三个生成器中的两个被允许切换，总体FT-NDCG增益为+0.000319（[-0.000077, +0.000720]），效果不确定。在A-Health类别上，三个生成器全部拒绝追加训练，避免了**1.7%的FT-NDCG损失**（强制追加的损失为-0.000644，[-0.000881, -0.000412]）。

## 四、展望

这项研究的深层启示在于：**训练时“帮助”模型的额外信息，可能通过参数共享在推理时产生不可预见的负面效应**。概率竞争并非目标监督本身的问题，而是监督机制设计中的陷阱。对于工程实践，论文给出的建议明确且可操作：候选补全应针对每个生成器单独评估，而非作为默认策略自动应用。未来，类似的损失分解思路或许可以推广到多源候选融合、辅助任务学习等更广泛的训练场景中——当多个目标共享同一组参数时，**如何界定“共享”的边界，可能比增加更多监督信号更重要**。
