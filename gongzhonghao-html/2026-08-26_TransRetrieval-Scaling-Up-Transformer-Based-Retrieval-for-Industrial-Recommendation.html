TransRetrieval: Scaling Up Transformer-Based Retrieval for Industrial Recommendation

📅 2026-08-28

阿里TransRetrieval强势落地：检索模型算力削减85%，Recall@2000暴涨19.3点的秘密

一、为什么检索阶段难以规模化？

大语言模型的成功背后，缩放定律（Scaling Laws）功不可没：模型容量、数据量和算力的增加，能够稳定带来性能提升。然而在推荐系统领域，这一规律却长期失灵。尤其是在大规模检索阶段，候选池规模可达 $10^8$ 量级，端到端时延预算仅为几十毫秒，模型每前向一步都要精打细算。

问题的根源之一在于特征异质性：推荐系统的输入包含用户画像、行为序列、物品属性等天然异构的字段，直接映射为 Transformer token 后，不同字段的 token 范数会出现数量级差异。例如用户侧 token 范数可达目标侧的 10 倍以上，注意力权重因此被高范数 token 主导，导致深层 Transformer 建模能力反而退化。

淘宝天猫集团与中国人民大学高瓴人工智能学院联合提出的 TransRetrieval，正是要破解这一难题。该框架在阿里展示广告平台落地，服务 4 个业务域，以相同的端到端时延约束，实现平台收入 2.53% 的提升，并在 40 亿交互的工业数据集上验证了检索阶段的对数线性缩放。

二、核心方法：三项轻量设计打通 Transformer 检索

TransRetrieval 的整体架构如图 X 所示。论文没有堆砌复杂的结构创新，而是从输入条件、计算瓶颈、域冲突三个维度入手，用三个轻量设计恢复了 Transformer 的缩放能力。

1. 加权平均聚合：恢复同质 token 假设

标准 Transformer 对同质 token 序列建模：NLP 中每个词向量来自同一查表表，视觉中每个 patch 经过同一投影。推荐特征天然异构，若采用传统的加权求和聚合，输出范数会随字段基数 $n_f$ 线性增长，用户侧多值特征因此产生远超目标侧的范数。

论文在剖析这一“尺度错位”后，提出加权平均聚合：

$$ \mathbf{e}_{f}=\frac{\sum_{i=1}^{n_{f}}v_{i}\cdot h(k_{i})}{\sum_{i=1}^{n_{f}}v_{i}+\epsilon} $$

该方法同时抵消了基数累积与异构权重幅度的影响，使输出范数仅由嵌入表分布决定，与字段基数无关。相比 LayerNorm、Max Pooling 等方案，加权平均无需学习或统计参数，是一个稳定的闭式线性组合，不丢失字段自身的幅度信号。

2. 目标 token 压缩：把算力从冗余处解放

在模型检索范式下，同一请求的所有候选共享同一个用户，因此用户侧 KV 只需计算一次并复用。每个候选目标仍需自己的 Q/K/V 投影、FFN 及对用户序列的交叉注意力。总 FLOPs 可近似表示为：

$$ \text{FLOPs}_{\text{total}}\approx 4D\cdot N_{\text{target}}\cdot L_{t}\cdot(4D+L_{u})\cdot N_{\text{layer}} $$

其中 $L_t$ 是目标 token 数。未压缩模型的目标 token 数随目标特征字段数增长，成为最值得压缩的因子。TransRetrieval 引入一个 3 层 MLP，将全部目标侧聚合嵌入映射为单个 token：

$$ \mathbf{t}=\text{MLP}\!\left(\left[\mathbf{e}_{f_{1}},\mathbf{e}_{f_{2}},\ldots,\mathbf{e}_{f_{M}}\right]\right)\in\mathbb{R}^{D} $$

这一压缩使 per-candidate FLOPs 削减约 85%，同时并非牺牲表达能力：释放的算力被重新投入到骨干网络的宽度和深度，换取更强的交叉特征交互。单 token 天然适配 HNSW 的定长向量索引，无需额外处理。

3. 位置式域嵌入：让跨域数据成为缩放资产

工业系统通常服务多个业务域，若为每个域维护独立模型，成本成倍增加；直接混合数据则会因分布冲突而失效。TransRetrieval 采用一种类似位置编码的策略——学习每个域对应的 $D$ 维向量，以元素加法注入所有 token：

$$ \tilde{\mathbf{e}}_{f}=\mathbf{e}_{f}+\mathbf{s}_{d} $$

该设计不增加序列长度和注意力复杂度，所有 Transformer 参数在域间无条件共享。每个样本对共享参数都有梯度贡献，稀疏域因此能受益于跨域迁移，而非因数据不足而训练不充分。

三、实验：对数线性缩放与真实收益

论文在阿里展示广告平台 40 亿交互工业数据集和公开 KuaiRand 基准上进行验证。工业数据集覆盖 4 个业务域、5200 万投放物品；KuaiRand 包含极端稀疏域，为跨域泛化提供严苛测试。

下表对比 TransRetrieval 与基线在相同或更小算力下的 Recall@2000：

方法 Industrial Overall R@2000 MFLOPs KuaiRand Overall R@2000 MFLOPs
Production Baseline 0.576 0.69 0.378 0.64
HSTU-128D5L 0.527 1.72 0.382 1.72
RankMixer-128D8T 0.452 2.10 0.364 2.10
TransRetrieval-64D3L 0.603 0.45 0.419 0.42
TransRetrieval-128D5L 0.657 1.91 0.473 1.81

TransRetrieval-64D3L 以 35% 更少的算力超越工业基线，128D5L 进一步将 Recall@2000 提升至 0.657。缩放曲线显示，从 32D-1L 到 128D-5L，工业数据集Recall提升 +19.3pt，KuaiRand提升 +22.2pt，两条曲线均呈稳定对数线性，拟合 $R^2$ 分别达 0.82 和 0.88。

值得注意的是，即使 RankMixer 扩至 768D-16T、算力高达 150.99 MFLOPs，其工业 Recall 仍只有 0.531，远低于 TransRetrieval-128D5L 的 0.657，而后者仅用 1.91 MFLOPs。这验证了目标 token 压缩后的算力再投资策略更具效率。

在线 A/B 测试持续一个月，TransRetrieval-128D5L 在相同 P99 时延（<40ms）下，平台收入提升 2.53%，RPM 提升 1.28%，且广告主 ROI 保持稳定。

四、技术价值与应用前景

TransRetrieval 证明了一件事：推荐检索的缩放瓶颈并非无法突破，关键不在堆叠复杂结构，而在恢复 Transformer 的前提假设、重构算力分配方式。加权平均是“一行代码”级别的输入修正；目标 token 压缩将算力解放并重新投入骨干；位置式域嵌入则把多域数据从负担变为资产。

这套设计全部使用标准算子，不依赖额外基础设施，对同处模型范式约束下的检索系统具有直接迁移价值。当检索阶段也能像大模型一样稳定缩放时，推荐系统的复杂特征交互或许将迎来新的扩张空间。

在算力预算持续增长、时延约束依旧苛刻的背景下，Retrieval 的下一阶段是否会进一步逼近生成式范式的表达能力？这值得持续关注。
