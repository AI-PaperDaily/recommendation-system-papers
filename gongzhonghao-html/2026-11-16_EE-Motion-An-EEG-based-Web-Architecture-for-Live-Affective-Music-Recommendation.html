EE-Motion: An EEG-based Web Architecture for Live Affective Music Recommendation

📅 2026-11-18

Wideverse 等参与的 EE-Motion：浏览器接入脑电调节音乐推荐，本地测试单轮平均低于 125 毫秒

一、引言

音乐推荐通常依赖播放记录、收藏和历史偏好，但一次听歌过程中的状态并不固定：同一个人可能刚开始需要安静的背景音乐，过一段时间又希望听节奏更强的歌曲。如果推荐系统只使用长期画像，就很难及时响应这种变化。

EE-Motion 尝试将可穿戴脑电设备接入浏览器，把持续变化的生理信号转换成推荐时可用的控制坐标。系统还允许匿名访客通过少量喜欢的歌曲初始化偏好，不必为新用户重新训练模型。

这项工作的重点是打通“浏览器采集—信号处理—候选排序”的链路，而不是证明机器已经准确读懂情绪。原论文使用的脑电指标未经个体校准，应理解为与情绪维度相关的代理信号，不能当作经过验证的情绪识别结果。

二、核心方法

Web 架构：把脑电采集与推荐排序分开

EE-Motion 将系统拆成四个服务：前端负责交互，曲库服务提供歌曲元数据，bci-processor 处理脑电信号，推荐服务则通过 WarpRec 对候选歌曲排序。服务之间通过 HTTP 和 WebSocket 通信，因此既可以部署在本地，也可以拆分到不同节点。

在脑电模式下，浏览器通过 Web Bluetooth 连接 Muse 2 头带，采集的数据被送往 bci-processor；后者输出二维坐标，再交给推荐服务。这样，排序模型不需要直接处理蓝牙通信或原始脑电波形。

二维坐标采用 Russell 情绪环模型中的两个维度：

  • 效价 Valence：描述情绪正负方向。
  • 唤醒度 Arousal：描述生理激活程度。

系统将两个代理指标映射到 $[0,1]\times[0,1]$ 范围。只要输入遵循相同格式，下游推荐服务就可以接收其他来源的坐标。演示中的手动模式正是利用这一点：访客拖动二维平面上的光标，就能观察不同坐标对推荐列表的影响，无须佩戴设备。

BCI 处理流程：从脑电波形得到二维代理坐标

Muse 2 使用 TP9、AF7、AF8、TP10 四个通道，以 256 Hz 采样。后端为每个通道维护 1024 个采样点，即约 4 秒的数据窗口；窗口填满后，系统将数据转换为 MNE 格式，利用 LOF 检测信号特征异常的通道，并结合人工观察检查噪声和佩戴位置。

预处理使用 1—40 Hz 的因果带通滤波，再估计 theta、alpha 和 beta 频段功率。第二个环形缓冲区保存连续 20 次特征观测，并分别按通道和频段取平均，以减弱短时波动；该缓冲区填满后才计算代理指标。

其中，额叶 alpha 不对称性用于构造效价相关指标：

$$\mathrm{FAA}=\log\left(\frac{\alpha_{\mathrm{AF8}}}{\alpha_{\mathrm{AF7}}}\right)$$

该式比较左右额叶通道的平滑 alpha 功率，作为效价相关的生理代理，而不是对正负情绪的直接测量。

唤醒度指数则由额叶 beta 与 alpha 功率之比得到：

$$\mathrm{AI}=\frac{\beta_{\mathrm{AF7}}+\beta_{\mathrm{AF8}}}{\alpha_{\mathrm{AF7}}+\alpha_{\mathrm{AF8}}}$$

该式用两个额叶通道的 beta 功率总和相对于 alpha 功率总和的比例，提供唤醒度相关的控制信号。

两个指标经过固定系数的 Sigmoid 映射后，成为归一化坐标。演示中，稳定后的坐标以 8 Hz 显示在二维平面上；这不意味着系统每 125 毫秒就能独立完成一次经过验证的情绪判断。4 秒采样窗口、连续观测平滑以及个体差异，都需要与显示刷新频率区分开看。

Affective Adapter：让匿名偏好和实时坐标共同参与排序

实时坐标解决的是“当前控制信号从哪里来”，却不能单独回答“这个人喜欢什么”。EE-Motion 的 Affective Adapter（情感适配器）因此同时接收三类输入：访客选择的歌曲、当前 V/A 坐标，以及预计算的歌曲嵌入和歌曲级 V/A 画像。

访客最多选择 10 首喜欢的歌曲。适配器通过聚合选中歌曲的嵌入来表示匿名偏好，其中使用均值投影到潜在空间的方式，绕过依赖固定用户嵌入表的限制。底层推荐模型仍需预先训练，但新访客进入时不需要重新训练模型或建立持久用户嵌入。

适配器还为不同模型提供统一的在线接口。演示支持具有不同结构的 ACE 和 SASRec：前者提供情感建模基础，后者属于通过交互序列建模的推荐架构。无论选择哪一种，系统都使用访客选曲和当前代理坐标生成 Top-10 列表。

原文没有给出完整的在线打分公式或各输入的权重，因此不宜把结果简单理解成“只按歌曲与当前坐标的距离排序”。推荐页支持播放、三级评价，以及按需使用当前坐标重新排序。会话重置时，系统会清除内存中的缓冲区、连接和用户数据；这些信号也不用于临床情绪评估。

三、实验

性能测试在 MacBook Pro M4 本地环境进行，以减少网络延迟的干扰；曲库使用带有推断歌曲级 V/A 画像的 Lastfm-VADS。测试关注一次从浏览器请求开始的推荐周期，并比较接入适配器的 ACE 与 SASRec。

两种模型的单轮平均耗时分别为 80.0±7.4 毫秒和 90.3±7.0 毫秒，均低于 8 Hz 更新周期对应的 125 毫秒；候选评分所在的推荐服务占据主要耗时。这说明在该本地测试条件下，平均处理速度能够跟上演示所需的更新频率，但这些结果不代表跨网络部署或高并发场景下的延迟表现。

推荐质量方面，研究使用 nDCG@10 衡量前 10 个推荐结果的排序质量。ACE 的在线版本与离线版本分别为 0.0231 和 0.0236，SASRec 分别为 0.0164 和 0.0148；Wilcoxon 符号秩检验均为 $p>0.05$。在该对比中未发现统计显著差异，但这并不等同于证明两种部署方式质量完全相同，也不能替代对真实情绪识别准确率的验证。
