Real-Time Hard Negative Sampling via LLM-based Clustering for Large-Scale Two-Tower Retrieval

📅 2026-07-05

Meta最新力作发布：LLM聚类+实时负采样，CTR狂飙53%，双塔模型还能这么玩？

当推荐系统的检索管道面临数十亿候选物品时，负样本的质量直接决定了模型的收敛边界。传统方法要么依赖于批次内采样的局限性，要么陷于随机负样本过于简单的困境。Meta研究者近期提出的Cluster GOOBS框架，通过引入LLM驱动的语义聚类和实时负采样引擎，在工业级数据上实现了堪比暴力枚举的难负样本质量，同时保持了极低的计算开销。该方法在Amazon Electronics数据集上取得了HR@50提升55.6%的惊人结果，并在真实工业流量中获得了53%的CTR增长。

一、核心方法：自监督聚类难负采样

1. 问题形式化与双塔模型困境

推荐系统中的检索模型通常被形式化为一个极多分类问题，标准的双塔模型架构将用户和物品分别编码为embedding，通过内积计算相关性。在训练时，模型需要优化的损失函数为交叉熵损失：

$$\mathcal{L}(\{x_i,y_i,r_i\}_{i=1}^n)=-\frac{1}{n}\sum_{i=1}^n r_i\cdot\log(P(y_i|x_i;\theta))$$

其中，每个正样本的概率计算需要面对整个候选物品集合$\mathcal{I}$：

$$P(y_i|x_i;\theta)=\frac{e^{s(x_i,y_i|\theta)}}{\sum_{j\in\mathcal{I}}e^{s(x_i,y_j|\theta)}}$$

在实际工业应用中，$\mathcal{I}$的规模可达数百万甚至上亿，精准采样是唯一可行的路径。但传统的in-batch和out-of-batch采样往往产生易于区分的负样本，导致模型无法学到物品间的细粒度区分。

2. LLM驱动的聚类生成

该方法依赖大语言模型（LLM）来构建高质量的语义聚类。不同于传统方法依靠物品类别或标签进行粗粒度聚类，研究者利用一个由LLM微调得到的多模态内容嵌入模型，能够处理文本、图像、视频等多种模态，生成语义丰富的物品表示。基于这些表示进行聚类，确保同一聚类内的物品具有高度的语义相似性。

在负采样时，对于每个正样本，从该正样本所在聚类中采样K个负样本。这些聚类内负样本天然具有硬负样本特性——它们与正样本在语义上接近，迫使模型学习更精细的决策边界。

3. 理论上：梯度信号最大化

研究者从对比学习理论角度解释了聚类负采样的有效性。在标准的InfoNCE或softmax交叉熵损失中，负样本$x_j^-$对于用户锚点$x_u$的梯度贡献与其指数化相似度$\exp(s(x_u,x_j^-))$成正比。随机均匀采样的负样本通常与锚点在嵌入空间中相距很远，导致其相似度趋近于零，因而几乎没有梯度信号更新模型。

通过从正样本相同的语义聚类中采样负样本，该方法确保了负样本与正样本共享潜在特征，使得模型在完全收敛前就能获得较大的相似度分数。这意味着负样本更接近模型当前的决策边界，产生的梯度幅度显著更大，迫使模型学习聚类内物品的细微差异，而非依赖简单的聚类间区分。

二、GOOBS：面向工业级部署的实时采样框架

理论上再精彩，如果不能落地都是空谈。该方法的另一大亮点是设计了GOOBS（Global Out-of-Batch Sampling）框架——一个能够无缝集成到生产模型、处理数十亿训练数据点的实时负采样系统。

GOOBS的核心是一个物品池，用于存储OOB样本的张量。每个物品被分配到特定的“槽位”，存储其所有特征。训练过程中，当处理每个mini-batch时，更新引擎通过定制的哈希函数将当前批次中的物品映射到其所属聚类对应的槽位上。

算法1：更新引擎实现了一个O(1)的写入过程：
- 获取物品的聚类ID
- 通过哈希函数映射到聚类对应的槽位
- 更新物品特征

与此同时，采样引擎接收当前批次物品的聚类ID作为输入，从物品池中对应的聚类段随机选取一个已存储的物品，搭配其完整特征，作为该批次样本的OOB负样本。

算法2：采样引擎同样高效：
- 获取当前批次样本的聚类ID
- 在对应聚类段内随机选择一个槽位
- 取出该槽位中的物品作为负样本

为了确保训练初期的采样命中率，物品池会在训练开始前从历史数据表中预加载物品特征。虽然这些数据可能略微滞后于最新训练数据，但in-batch样本本身持续更新池中的内容，确保其新鲜度。这一设计使得GOOBS能够在全量负样本和实时性之间取得精确平衡。

三、实验与工业部署

1. 公共数据集上的压倒性优势

研究者在MovieLens-1M和Amazon Reviews的多个子集上进行了实验，将Cluster GOOBS与以下方法对比：
- 基线：In-batch负采样 + LogQ校正
- DNS：动态负采样
- CBNS：跨批次负采样
- ANCE：近似最近邻负采样
- GOOBS：随机OOB采样

2. 工业A/B测试：53% CTR提升与流行度偏置纠正

在Meta的工业推荐系统中，候选物品池约有1800万条内容，然而前100个物品就占了总展示量的50%。这种极端的流行度偏置导致长尾内容几乎无法获得曝光，形成了难以打破的系统反馈循环。

实验中，控制组使用随机OOB采样的GOOBS，测试组使用Cluster GOOBS，各覆盖3%的用户。LLM聚类生成了300个语义聚类，其中98%的聚类包含1万以上物品。

Cluster GOOBS不仅带来了53%的CTR提升，同时仅引入了1.4%的训练QPS损失，推理时无任何QPS退化。更重要的是，通过提供更难的负样本，模型被迫学习更细致的用户偏好信号，有效打破了系统反馈循环——前100个热门物品的展示贡献从50%降至32%，而展示量≥1k的长尾物品数量增长了50%。

四、技术价值与应用展望

Cluster GOOBS展示了语义聚类在大规模推荐系统中的巨大潜力。从技术角度看，该方法：
- 无需全局索引，避免了ANCE等方法的维护成本
- 实时在线生成，不需要预计算或辅助模型
- 可解释性优于基于embedding距离的硬负采样
- 自然缓解流行度偏置，打破系统反馈循环

未来的探索方向包括加权聚类负采样和基于用户查询的个性化负采样，这将进一步提升负样本的针对性与质量。对于正在与推荐系统偏置和负样本质量作斗争的工程师而言，Cluster GOOBS提供了一个直接且高效的解决方案。
