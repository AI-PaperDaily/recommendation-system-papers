Scaling Graph Neural Networks for Friend Recommendation: Multi-Hash User Embeddings and Temporal Neighbor Sampling

📅 2026-08-31

一、核心方法

论文提出的GNN排序系统围绕两个关键设计展开：多哈希ID嵌入与时间邻域采样。前者压缩99%的嵌入表存储，后者将采样复杂度从线性降至对数级，二者共同支撑起在194M节点、28B边规模上的端到端训练与推理。

多哈希ID嵌入

在社交网络场景中，用户画像特征弱、节点身份信息强，但为2亿用户维护可训练的完整ID嵌入表超出了一个内存单位能够承载的范围。论文采用多哈希方案：用$k$个独立哈希函数将用户ID映射到一个共享表$T\in\mathbb{R}^{B\times d}$中，取$k$行拼接后投影回隐层维度：

$$e_{u}^{\text{hash}}=T_{r_{1}(u)}\|T_{r_{2}(u)}\|\cdots\|T_{r_{k}(u)}\in\mathbb{R}^{kd}$$ $$z_{u}^{\text{emb}}=\operatorname{LayerNorm}(W_{h}e_{u}^{\text{hash}}+b_{h})$$

在$k=3$、$B=2^{21}$、$d=256$的配置下，哈希表仅占2GB，相比完整表的202.88GB缩小超过98%。消融实验显示，多哈希+特征的ROC-AUC为0.6278，而使用完整嵌入表仅得0.6246——共享表的受限容量反而充当了隐式正则化，防止了逐行过拟合。

时间邻域采样

训练样本带有印象时间戳$\tau$，任何在$\tau$之后形成的边若被纳入消息传递即构成未来信息泄漏。朴素做法是扫描整个邻接表并按时间过滤，对度数上万的枢纽用户来说代价不可接受。论文将每个用户的邻居按时间戳升序存储于CSR结构，采样时先二分查找定位合法前缀边界：

$$\mathcal{N}_{<\tau}(u)=\{v\in\mathcal{N}(u):t_{uv}<\tau-\Delta\}$$ $$\mathcal{O}(\log d_{u}+K)\;\text{vs}\;\mathcal{O}(d_{u}+K)$$

在$d_{u}\sim 10^{4}$、$K=30$的典型配置下，二分查找采样器的每批耗时595ms，与无时间约束的非时序版本（581ms）几乎持平，而朴素扫描则需1473ms——近2.5倍的开销。

二、实验

论文在194M用户、28B边、14亿训练印象的生产规模上进行了全面对比。离线评测使用逐用户ROC-AUC指标：

方法 ROC-AUC
Top-pop 0.5050
MF（矩阵分解） 0.5316
WalkGNN（旧生产基线） 0.5572
本文模型 0.6278

消融实验进一步验证了两个核心组件的贡献。在共享表容量扫描中，质量随$B$从$2^{17}$增至$2^{22}$单调上升，$B=2^{21}$时ROC-AUC达0.6278，$B=2^{22}$虽略升至0.6310，但表内存翻倍至4GB，边际收益递减。

在系统层面，训练收敛共用时63小时（早停于252k迭代），全量194M用户嵌入刷新需6.57小时。CSR图占CPU侧225GB，而可训练参数总计仅6.03GB，单GPU即可容纳。

在线A/B测试运行两周，结果如下：

指标 相对变化
推荐带来的好友添加量 +16.0%
添加好友的独立用户数 +11.5%
内容信息流总时长 +0.28%
排序器p50/p90/p99延迟 无退化

由于GNN信号以预计算嵌入形式提供给排序器，在线路径仅做内积运算，延迟与对照组无显著差异。内容信息流时长的提升被论文视为下游效应——用户形成了更多连接，自然获得更多内容供给。

三、展望

这项工作证明了两点：第一，工业规模GNN的瓶颈往往不在消息传递层的选择，而在身份表示的内存效率与时序正确的采样代价这类工程决策上；第二，哈希碰撞在超大ID空间中并非妥协，而是可被利用的正则化。论文已开源框架，涵盖CSR时间采样器、多哈希嵌入层及分布式训练管线，可供其他工业GNN团队直接复用。值得关注的是，新用户的冷启动问题依赖周期性重训练缓解，未来若结合增量嵌入折叠或连续记忆更新机制，有望进一步压缩“冷窗口”，这将是工业部署中值得追踪的方向。
