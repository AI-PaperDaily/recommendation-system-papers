MATE: Adaptive Long- and Short-Term User Memory for LLM-Based Recommendation

📅 2026-10-07

MATE框架重塑LLM推荐：双时间证据驱动记忆自适应，NDCG@10最高提升13.2%

推荐系统长期面临一个根本性难题：用户行为序列中，哪些交互代表稳定偏好，哪些只是短期兴趣的瞬时波动？传统方法通常按时间远近一刀切——早期交互归入长期记忆，近期交互归入短期记忆。这种粗粒度划分忽略了一个关键事实：同一行为可能同时具备长期偏好和短期兴趣的双重属性。例如，一位用户多年前购买过OPI指甲油，最近又频繁浏览essie产品，当再次出现OPI相关互动时，这既是对历史偏好的回归，也可能只是近期美妆兴趣的延伸。

论文提出的MATE（Memory Adaptation with Temporal Evidence）框架，通过时间证据驱动的双记忆自适应机制，为这一问题提供了新解法。在MovieLens-10M、Amazon Luxury Beauty和KuaiRec三个数据集上，MATE的NDCG@10指标相对最强外部基线提升7.0%–13.2%。

一、核心方法：时间证据如何驱动记忆更新

MATE的设计核心是将用户建模视为持续自适应过程，而非对历史序列的固定编码。框架包含三个阶段：时间证据计算、双记忆更新、上下文感知推荐。

1. 时间证据：从行为模式中识别偏好属性

论文摒弃了按时间戳硬性划分用户行为的方式，转而从两个独立维度评估每次交互的“时间角色”。

短期证据衡量当前交互与近期行为的语义一致性。给定最近窗口 $\mathcal{R}_{u,t}$，计算窗口内与当前物品语义相似的比例：

$$C^{S}_{u,t}=\frac{\sum_{j\in\mathcal{R}_{u,t}}\mathbb{I}\left[\mathbf{e}_{u,t}^{\top}\mathbf{e}_{u,j}\geq\delta\right]}{|\mathcal{R}_{u,t}|}$$

最终短期证据 $w^{S}_{u,t}=\epsilon+(1-\epsilon)C^{S}_{u,t}$，其中 $\epsilon>0$ 保证新涌现的兴趣即使没有相似历史也能获得最低写入强度。这一设计体现了对“冷启动兴趣”的包容——用户突然转向新品类时，短期记忆仍能响应。

长期证据则关注跨时间段重复出现的行为模式。论文将历史交互按日历月分组，统计有多少个月份包含与当前物品语义相关的交互。只有当支持月份数达到阈值 $K_L$ 且时间跨度超过 $\Delta_L$ 时，才赋予非零长期证据：

$$w^{L}_{u,t}=\begin{cases}\displaystyle\frac{N^{L}_{u,t}}{|\mathcal{M}_{u,t}|},&N^{L}_{u,t}\geq K_{L}\text{ and }\operatorname{span}_{u,t}\geq\Delta_{L},\\ 0,&\text{otherwise},\end{cases}$$

这一设计的精妙之处在于：密集爆发式的相似行为不会立即被视为长期偏好，只有跨时间段的重复出现才能触发长期记忆写入。理论分析（定理1）进一步证明，在稀疏月度匹配条件下，长期写入的期望强度受二次上界约束，有效抑制了偶发行为的过度写入。

2. 双记忆自适应：差异化动力学分离记忆职责

MATE为用户维护两个独立的快速权重矩阵：长期记忆 $\mathbf{M}^{L}_{u,t}$ 和短期记忆 $\mathbf{M}^{S}_{u,t}$。两者的更新遵循同一数学形式，但采用截然不同的动力学参数：

$$\mathbf{M}^{L}_{u,t}=(1-\eta_{L}\gamma_{L})\mathbf{M}^{L}_{u,t-1}+\eta_{L}w^{L}_{u,t}\mathbf{e}_{u,t}\mathbf{k}_{u,t-1}^{\top}$$ $$\mathbf{M}^{S}_{u,t}=(1-\eta_{S}\gamma_{S})\mathbf{M}^{S}_{u,t-1}+\eta_{S}w^{S}_{u,t}\mathbf{e}_{u,t}\mathbf{k}_{u,t-1}^{\top}$$

两个记忆的差异化体现在 $\eta$ 和 $\gamma$ 的取值上。论文设定 $(\eta_L,\gamma_L)=(0.03,0.001)$ 和 $(\eta_S,\gamma_S)=(0.15,0.1)$，意味着长期记忆的衰减因子 $\rho_L=1-0.03\times0.001\approx0.99997$ 接近完美保留，而短期记忆的衰减因子 $\rho_S=1-0.15\times0.1=0.985$ 则允许更快速的遗忘。定理2给出了记忆更新的稳定性保证：单次写入对后续状态的影响被保留因子 $\rho$ 的幂次所控制，长期记忆的影响衰减远慢于短期记忆。

3. 上下文感知读取：动态分配记忆贡献

记忆写入解决“存什么”的问题，而记忆读取解决“用多少”的问题。MATE通过一个轻量门控网络，根据当前上下文动态决定两个记忆的读取权重：

$$\left[\alpha^{L}_{u,t},\alpha^{S}_{u,t}\right]=\sigma\left(\operatorname{MLP}(\mathbf{q}_{u,t})\right)$$

两个权重独立估计，不受总和为1的约束约束。这意味着模型可以同时强调两个记忆、仅激活其中一个，或在两者相关性较低时同时降低贡献。最终用户表示为：

$$\mathbf{h}_{u,t}=\operatorname{Norm}\left(\mathbf{W}_{\mathrm{down}}\mathbf{k}_{u,t}+\alpha^{L}_{u,t}\mathbf{M}^{L}_{u,t}\mathbf{k}_{u,t}+\alpha^{S}_{u,t}\mathbf{M}^{S}_{u,t}\mathbf{k}_{u,t}\right)$$

写入与读取的分离是MATE的关键设计：时间证据决定写入强度，上下文门控决定读取强度，两类信号互不干扰。

二、实验：三数据集验证与消融分析

整体效果

在MovieLens-10M、Luxury Beauty和KuaiRec三个数据集上，MATE在所有报告指标上均取得最佳均值表现。相对最强外部基线，NDCG@10分别提升约8.6%、13.2%和7.0%。值得注意的是，最强基线在不同数据集上并不固定——TTT4Rec在MovieLens-10M领先，PCTM在Luxury Beauty占优——MATE的优势并非针对单一弱者。

与共享骨干网络的Base相比，MATE的NDCG@10提升幅度达93.8%（MovieLens-10M）、46.6%（Luxury Beauty）和28.1%（KuaiRec），验证了自适应记忆机制的实质性贡献。

消融实验

表3揭示了各组件的重要性排序。移除时间证据（$w^{L}=w^{S}=1$）导致NDCG@10下降4.4%–19.0%；移除时间监督损失（$\lambda=0$）下降6.6%–25.4%；固定读取权重（$\alpha^L=\alpha^S=0.5$）造成最严重的性能损失，NDCG@10下降32.5%–56.3%。这表明上下文感知的动态读取是MATE最关键的机制。

一个值得关注的发现是：Frozen Online Memory（测试阶段冻结记忆更新）与MATE在报告精度上完全一致。这意味着已适配的记忆状态本身已足够支撑推荐质量，测试期的持续写入未带来额外的Top-10收益。论文对此保持客观态度，明确指出“这些实验并未建立持续测试时写入的额外益处”。

效率与存储

MATE每用户使用1.0 MiB浮点32自适应记忆，相对Base增加约1.25–1.32 ms/事件的处理开销。候选评分时间变化不超过3.0%，额外成本主要来自事件处理阶段的记忆更新计算。

三、用户适应验证：找回“被遗忘的偏好”

论文通过“继续B”和“返回A”两个场景检验适应与保留的平衡。当用户历史中存在主题A（跨月重复出现）和主题B（近期连续出现）时，MATE在预测B的延续和A的实际回归两类目标上均超越Base和Single。在MovieLens-10M上，MATE对“返回A”的NDCG@10达到0.0049，相对Base提升53.1%。

表5的诊断统计揭示了数据集间的行为差异：MovieLens-10M和Luxury Beauty中，62–65%的测试事件触发了长期写入，而KuaiRec仅有6.1%。然而，所有数据集上短期记忆的读取贡献均显著大于长期记忆，表明短期信号在排序中的主导地位。

定性案例进一步说明了双记忆的协作方式。在Luxury Beauty的一个真实用户场景中，2016年的OPI和essie交互后，2018年再次出现的OPI交互触发了完整长期写入（$w^L=1.0$）。在后续预测中，短期读取贡献（3.242）是长期读取贡献（0.157）的20.7倍，但两者同时激活，使目标物品的排名从Base的第18位提升至MATE的第2位。

展望

MATE的时间证据驱动双记忆架构为推荐系统中的用户建模提供了新思路：将记忆更新从固定规则中解放出来，让行为本身的时间模式决定其应有的持久性。这一框架的潜在应用不仅限于推荐系统，任何需要维护用户状态并根据行为调整的交互式系统——如对话系统、个性化搜索、自适应学习平台——都可能从中受益。

论文也留下了一个值得思考的问题：在离线训练已充分适配的情况下，在线持续写入的增量价值究竟有多大？这一问题的答案，可能取决于真实场景中用户偏好的演化速度是否超过了训练数据所能覆盖的范围。
